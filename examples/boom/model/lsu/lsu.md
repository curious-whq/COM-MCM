## 第一轮重点可疑项

1. **规范 1643–1692 `dcache_valid_requires_tlb_hit`**：RTL 在 load agen/retry 中可先令 `dmem_req.valid := true`，再通过 `s0_kills := exe_tlb_miss || ...` 杀掉请求，因此若规范的 `DCacheReqValid` 对应 `dmem_req.valid`，则“valid 必须已有 TLB hit”过强。
2. **规范 1693–1800 `accepted_request_marks_executed`**：RTL 中 request fire 只产生 `s0_executing_loads`；下一周期 `s1_set_execute` 还可能因 older load、store conflict、AMO/fence 等被清掉，所以 `fire -> +1 cycle LoadExecuted exact` 过强。
3. **规范 3311–3380 `store_tlb_hit_requires_retry_issue`**：RTL 的首次 store address generation 同样可以 TLB hit，不要求先经过 retry queue；该规范前置关系明显过窄。
4. **规范 4955–5103 older AMO block**：RTL `stq_amos = is_fence || is_amo`，即 older fence 与 older AMO 都会阻塞 load；规范这里只使用 `${store.is_amo}`，没有 fence×load 对应规则，存在漏建模风险。
5. **规范 3962–4155、4295–4653 的地址匹配**：RTL 使用同一 8-byte dword + byte-mask overlap；规范调用 `same_address` + `mask_overlap`。若 `same_address` 是完整字节地址相等，而不是 dword 对齐地址相等，会漏掉部分重叠访问。
