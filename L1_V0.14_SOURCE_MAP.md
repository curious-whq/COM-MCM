# BOOM L1 v0.14 source → µMCM map

Source SHA-256: `82d5562b6d6220be5714716c6b935a001ed6fc54747b4fc925603cabbde9aac4`

The v0.14 L1 model is an operational memory-order abstraction of the supplied BOOM v4 non-blocking DCache source. It intentionally models events/state that can affect request acceptance, response/replay, coherence observation, writeback, or ordering. It is not a bit-accurate copy of every SRAM/control signal.

## Important semantic choices

- `valid/ready/fire` are ordinary `Transformation` guards/events; there is no separate handshake semantics.
- Hit, miss, and nack are alternative S2 outcomes. v0.14 instantiates only the path classes requested by the bounded input Trace, avoiding the cross-product of every possible L1 branch.
- A replayed store does **not** emit a second StoreAck. The initial miss may be acknowledged when the MSHR accepts it; the later replay performs the cache data write.
- Store→Load bypass is guarded by temporal availability: the store write must already exist no later than the load S2 observation. A younger store cannot be forced to bypass an older load.
- Probe clean/miss/dirty paths preserve the ordering-relevant distinction between direct ProbeAck and WritebackUnit-mediated release.

## Deliberately abstracted

- exact metadata coherence encoding and replacement-policy implementation;
- individual SRAM bits and row/way contents except values carried by witness events;
- detailed arbitration fairness/backpressure histories when only existence of a feasible grant matters;
- prefetcher behavior;
- full LR/SC liveness/backoff timing beyond reservation validity/address and SC result;
- TileLink manager implementation below the L1 boundary.
