# BOOM v4 L1D source map for v0.21

The executable model is `examples/boom/model/l1/generic_v021.yaml`, instantiated by `examples/boom/composition/l1_source_v021.yaml`. It is derived from BOOM commit `58ef2720eae13be26b3008c02b5a74ce29c61c44`; the pinned `dcache.scala` SHA-256 is `82d5562b6d6220be5714716c6b935a001ed6fc54747b4fc925603cabbde9aac4`.

This replaces the witness-shaped v0.15 L1 for new source-model work. It is general over the finite sets, requests, probes and MSHR writes present in a query. There are no fixed older/younger load identities, fixed MSHR IDs, or supplied hit/miss outcomes.

## State and interface boundary

Private state is indexed by modeled set and way: replacement way, tag, coherence permission and line value. Pipeline, tag-match, hit, nack-cause, store-ack/store-write cause, replay-pipeline, ProbeUnit and physical data-write events remain private. LSU sees only request ready/fire, response/nack/store-ack/release; the MSHR side sees admission, request/replay and public meta/refill/writeback signals.

The tag/permission decision is state-derived. A load hits only a valid matching way. A store/SC/AMO hits only with stable write permission; otherwise a matching-tag permission request is sent to the MSHR. A tag miss selects the modeled replacement way and carries the victim dirty bit. MSHR not-ready, incoming probe metadata write, victim/secondary conflict, data-bank conflict and writeback-set conflict derive nacks.

## Intentional abstractions

- The current bound is four ways, matching the pinned Small/Medium BOOM DCache geometry. `DCache.ConfigInit` explicitly binds LSU width, data-bank count, single-port selection, 64 sets, four ways and two MSHRs; a multiport bank conflict cannot be selected under the one-wide SmallBoom configuration. A query instantiates only the finite sets it uses; it does not allocate all 64 physical sets.
- Cache-line values replace SRAM rows, ECC bits, byte masks and load sign extension. This preserves the memory-order data source but is not an ECC implementation.
- Ready/valid backpressure may stutter. Fixed source pipeline distances are retained after a request fires.
- Store/AMO arithmetic and LR/SC reservation success are owned by the v0.17 atomic module. L1 treats their accepted cache access as a read/write-kind request.
- TileLink A/D/E routing is owned by `tilelink_wiring_v021.yaml`; MSHR entry state is owned by the detailed MSHR model and allocator.
- `DCache.Ordered` still belongs to the pending full L1/MSHR integration because it is the conjunction of an empty s1/s2 pipeline and `mshrs.io.fence_rdy`.
- Prefetch, HellaCache/debug/performance counters and physical timing are outside the memory-order surface.

## Focused executable cases

The source-model traces cover ordinary hit, dirty replacement miss, permission miss, store hit, two-set isolation, MSHR refill followed by hit, lower-port bank conflict, clean Probe invalidation and dirty Probe downgrade. Integrated cases cover ordinary-store TLB retry and a cold store whose accepted MSHR request acknowledges the STQ before RPQ replay writes the retained SDQ value and marks the selected way dirty. In the Probe, refill and replay tests, later state or data checks ensure the model does not merely make an event name reachable.
